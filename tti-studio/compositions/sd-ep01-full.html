System design is deciding a system's parts, how they connect, and how data flows — so it works as users grow.

The words the whole field is built on
latency
How long one answer takes. (milliseconds)
throughput
How many answers per second. (the crowd)
Goal: maximum throughput, with acceptable latency. — System Design Primer

Two altitudes of design

There are two kinds of system design.

The big picture.
Boxes & arrows: which parts exist and how they talk. → this whole season.
LLD · low-level
Inside one box.
The actual classes & code for a single part. → Season 3.

The process — every single time

Good designers follow the same four steps.

The 4-step framework recommended by the System Design Primer — it expands into requirements → capacity → HLD → data/API → LLD → trade-offs → scale → iterate.
The #1 beginner myth

"Premature optimization is the root of all evil."

…so never bother optimizing, right?  Wrong.
Knuth's full line: forget the small stuff ~97% of the time — "but we should not pass up our opportunities in that critical 3%."
Donald Knuth, 1974. The 3% / 97% are illustrative, not measured.
